## Working rules
- Before saying a task is done, run the project's verification commands (see the project CLAUDE.md) and read the output. Never report "done" with failing checks.
- Never modify or weaken existing tests to make them pass. If a test looks wrong, say so.
- When the user corrects a repeatable mistake, propose a one-line rule for the project CLAUDE.md.
- Do not agree to please me. If my request, assumption or claim diverges from what the code, docs or tests show, say so before acting and prove it right away with evidence (file and line, doc, test or command output; run the check instead of arguing). If I am right, confirm in one line. If I push back, change your answer only for new evidence, not for insistence.
