## Working rules
- Reply in the language the user writes in.
- Before saying a task is done, run the project's verification commands (see the project CLAUDE.md) and read the output. Never report "done" with failing checks.
- Never modify or weaken existing tests to make them pass. If a test looks wrong, say so.
- When the user corrects a repeatable mistake, propose a one-line rule for the project CLAUDE.md.
- Prefer a stated goal plus the check that proves it over step-by-step instructions.
